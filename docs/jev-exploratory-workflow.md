# Exploration Jev, séparée de la validation humaine

Chemin : Plus / Thêm → Test Jev → Exploration Jev — avis à vérifier.

1. Sélectionner un dataset anglais figé puis **Créer l’exploration**. Sources initiales : les avis Artisan préparés dans l’expérience existante, ou un rapport V11 terminé. Aucune annotation ni finalisation humaine n’est requise. Aucune lecture des avis live et aucun backfill automatique.
2. Pour Artisan, **Lancer l’analyse Jev V11**, puis confirmer la consommation Jev. Le worker serveur analyse les 25 thèmes, 3 répétitions, concurrence 8, avec les questions et seuils V11 existants. V9 n’est pas relancé ; sa comparaison n’existe que si ses réponses persistées correspondent au même texte. Pour le rapport V11 terminé, les résultats existants sont réutilisés sans appel modèle.
3. Consulter les avis signalés : texte anglais, identifiant, note Google descriptive, choix, probabilités et motifs. Les règles `jev-suspects-v1` signalent les désaccords disponibles, les choix instables ou une dérive de probabilité ≥ 0,20, les résultats incomplets/incohérents, les présences à moins de 0,10 du seuil, et les critiques potentiellement manquées (notes faibles ou indices lexicaux anglais sans détection négative). Les signalements ne créent ni finding ni correction.
4. Sélectionner les avis puis **GO — autoriser la réanalyse ChatGPT** et confirmer. Télécharger/copier le dossier et le transmettre soi-même à ChatGPT. L’app ne fait aucun appel ChatGPT/Sol. Le dossier contient les questions V11 et un format de réponse JSON ; les avis sont identifiés comme des données non fiables, jamais des instructions.
5. Importer le JSON obtenu. `experiment_id`, `approval_id`, `bundle_sha256`, `dataset_sha256` doivent correspondre au dossier. Chaque correction nécessite `review_id`, `theme_key`, `analysis_text_sha256`, `initial_prediction` inchangée (ou null si indisponible), `choice`, `justification`, `corrected_at`, `corrector_model` exact déclaré et `label_source: chatgpt_ai_correction`. Aucun import sans GO enregistré ; aucune réécriture d’un import. Un nouveau dossier autorisé permet une nouvelle révision séparée.
6. Lire les **écarts exploratoires avec les corrections IA**. Ces métriques portent uniquement sur les labels corrigés, excluent uncertain et les prédictions indisponibles, et ne comptent pas les true negatives dans le F1. Elles ne sont pas une mesure indépendante ni une performance validée humainement. La dernière correction importée pour un couple avis/thème est utilisée ; toutes les révisions restent conservées.

Les sept nouvelles tables `analysis_jev_exploratory_*` conservent dataset, tâches, GO, corrections, événements et réservations. RLS owner/admin/manager, écritures uniquement via API sécurisée ; RPC worker réservées au service serveur. Le dataset et les résultats terminés sont immuables. Les réponses réseau payantes ambiguës ne sont pas rejouées automatiquement. Un GET, rechargement ou retour PWA ne lance aucun modèle. Les dossiers autorisés et corrections restent accessibles après rechargement.

La réservation pour une **future version explicitement choisie** ne crée pas cette version et ne change pas V11. Les mêmes review IDs ne peuvent pas servir à la calibration et à l’évaluation de cette version. Dès le GO de réanalyse IA, ils ne peuvent plus devenir une évaluation indépendante. Les holdouts indépendants déjà préparés sont protégés contre une réservation en calibration. Une tentative d’import sur un avis réservé à l’évaluation est bloquée. Ces protections couvrent ce parcours ; un futur moteur devra aussi utiliser ce registre pour constituer ses datasets.

Les parcours humains historiques restent disponibles dans « Ancien parcours humain — historique conservé ». Leurs guards de finalisation, labels et résultats ne sont pas modifiés. Les préannotations IA existantes ne sont ni importées automatiquement ni promues en labels humains. Aucun rapport historique n’est créé ou remplacé par l’exploration.

Déploiement : migrations de schéma uniquement, deux Edge Functions, frontend. Vérifications sur fixtures synthétiques et transactions SQL annulées ; aucun dataset réel créé, aucune annotation, aucun GO, aucun appel Jev/Sol/Apify pendant le déploiement.
