The holdout uses frozen V7 snapshot `b73ec894-d5fd-4b11-9fe6-cd89c117e9de` and frozen Jev Phase2 `4c634678-17a9-47b3-89e1-fad0641f5d86`. Its selection module accepts only English analysis text and previously seen review IDs. It never imports model-scoring code. It sorts SHA256(`source_generation_id + ':representative-holdout-v1:' + review_id`) ascending. All Gold review rows and all previous adjudication rows are excluded, including translation exclusions. The actual eligible pool is 55/95 textual reviews; the previous12 are already among Gold40, so exclusions must not be subtracted twice. These are a small independent sample of the remaining pool, not an estimate of global accuracy or theme prevalence.

Manual path: Plus / Thêm → Test Jev → Shabu → V7 · Analyse EN → Phase2 → Gold results → human-control results → Test représentatif → Commencer le test représentatif. Merely opening, reloading or foregrounding the screen sends GET only. No production holdout, selection rows or labels are created during deployment.

`representative-human-test` requires an authenticated owner/admin/manager of the source organization. The tables have RLS, no raw authenticated/anonymous privileges and no client RPC write grants. The API exposes only English text, frozen taxonomy and the user's own labels during draft. Predictions are loaded only on explicit finalization after12 confirmed reviews. Model outputs and comparison are never returned before completion.

Each explicit review confirmation writes all25 labels atomically (unselected=absent) plus annotator, timestamps, revision and an audit event. Translation exclusions retain their audit and get the next never-used candidate in hash order. Validated work and active items are server-persisted; local storage holds only user-scoped navigation position. Row locks, optimistic revision checks and unique active positions prevent duplicate creation and stale writes. Finalized parents and children are protected by triggers. All comparisons are calculated from persisted data without a provider call and stored once.

Primary metric is presence micro F1 using TP/FP/FN, excluding uncertain labels. Macro F1 requires human support>=3. Jev averages its three repetitions' positive+both and negative+both probabilities before applying0.50; it does not count repetitions as reviews. Secondary exact agreement is labelled separately. The paired bootstrap uses2000 samples of12 reviews each, with a SHA256(test_id) seed. An undefined-F1 sample forces an inconclusive verdict. Previous difficult-test exact agreements are read from that completed comparison and displayed separately from holdout F1.

Validation: synthetic unit/API/UI fixtures and mobile browser fixtures only. No calls to OpenAI, Jev or Apify, no historical/report/review/benchmark/old-Gold mutations. No automatic production switch.
